# 本地视频生产

本机使用 RX 9070 XT、Wan 2.2 TI2V 5B 和 ComfyUI 生成画面。默认六个镜头，每段 121 帧 / 24fps（约 5.04 秒），拼接后约 30.25 秒，480×832 竖屏、H.264 MP4。基础画面流程不生成配音或音乐；双角色 MiMo 配音和字幕流程见 [配音字幕与猫咪动画](配音字幕与猫咪动画.md)。

## 使用

1. 双击根目录 `start-comfyui-gpu.cmd`，等待 `http://127.0.0.1:8189` 就绪。如果已经运行，直接使用现有服务。
2. 双击 `generate-video.cmd`，使用示例剧本生成一条新视频。每次自动创建一个以北京时间命名的目录。
3. 查看 `runs/<批次名称>/final/film.mp4`。

也可在项目根目录的 PowerShell 中指定剧本和批次名称：

```powershell
& .\ComfyUI\.venv-rocm\Scripts\python.exe -u services\media\produce_video.py --storyboard prompts\stories\red_panda_morning.json --run-id 20261004_red_panda_morning_001
```

复用同一个批次名称和相同输入，可继续等待已提交的任务并复用成功片段。修改剧本或参数后，请使用新的批次名称。遇到生成错误，先查看该批次的 `logs/` 和 ComfyUI 控制台；修复后可在原命令末尾加 `--retry-failed` 重试已明确失败的镜头，旧任务记录会保留。脚本不会自动重复提交失败任务。建议一次运行一个生产任务，避免多批次挤占显存。

## 目录约定

```text
AIMedia/
├─ config/local_video.json            # 模型、分辨率、帧数、采样和本地服务参数
├─ prompts/stories/                   # 可复用剧本和分镜 JSON
├─ services/media/produce_video.py    # 提交镜头、保存记录、提取末帧、拼接
├─ workflows/comfyui/                 # 可手工导入 ComfyUI 的工作流
├─ docs/                             # 环境和使用说明
├─ samples/                          # 原有已归档云端 MVP 样片
├─ runs/<批次名称>/                   # 每次生成的独立档案
│  ├─ script.md                      # 中文剧本、分镜和镜头描述
│  ├─ storyboard.json                # 本次剧本快照
│  ├─ config.json                    # 本次参数快照
│  ├─ manifest.json                  # 任务 ID、状态、时长和文件校验值
│  ├─ prompts/                       # 实际提交的每个镜头工作流
│  ├─ clips/                         # 每个约 5 秒的 MP4
│  ├─ references/                    # 每段末帧，供下一段图生视频衔接
│  ├─ logs/                          # 每个任务的执行记录
│  └─ final/film.mp4                 # 最终成片
├─ ComfyUI/                          # 本地软件、虚拟环境、模型及原始输出
├─ .runtime/                         # 本地 Python 运行时
└─ .cache/                           # 下载和安装缓存、服务日志
```

`runs/`、`ComfyUI/`、`.runtime/` 和 `.cache/` 不进入 Git。生成文件全部留在项目目录。ComfyUI 的原始视频还会保存在 `ComfyUI/output/video/<批次名称>/`；便于使用的副本和最终成片集中在 `runs/`。

## 编写下一条视频

复制 `prompts/stories/red_panda_morning.json`，修改标题、梗概、统一风格和 `shots` 分镜列表。每个镜头包含中文标题、画面说明、镜头说明和英文生成提示词。六个镜头约 30 秒，增加或减少镜头会相应改变总时长。

`config/local_video.json` 的 `use_previous_frame` 默认为 `true`：从第二个镜头开始，使用前一段末帧作为首帧，有助于保持主体与环境连续，但模型仍可能偏离分镜或出现细节变化。第一段使用文生视频。

如需换题材、模型或参数，使用新批次保留历史记录。实际生成耗时以当前显卡和运行日志为准。
