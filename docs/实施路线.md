# AI 自媒体自动化实施路线

更新日期：2026-09-29。状态：方案设计，尚未安装服务或调用付费 API。

## 1. 已确认的需求

- 自己运营账号，后续可以扩展，但第一阶段不是对外销售 SaaS。
- 视频质量优先，使用 Seedance 2.5 这类高质量视频模型 API；不把图片缩放拼接作为默认交付效果。
- 覆盖内容计划、生成、配音、合成、质检、发布、数据回收的完整自动化流程。
- 优先复用成熟项目和工作流，不从零重造可视化平台。
- 题材暂不决定，内容规则、画风和声音应当可以配置。
- 全自动发布执行是生产流程最后一步的必需能力：初次账号配置完成后，正常任务无需人工上传、填写或点击发布。具体发布技术栈后续决定，不要求采用 Video Publisher Skill，也不为不兼容 Windows 的候选工具专门迁移环境。

## 2. 推荐决策

采用 n8n + ComfyUI + 小型 Python 媒体服务 + PostgreSQL + 对象存储。

- n8n：日程、内容计划、API 调用编排、等待结果、条件分支、发布调度、数据回收。
- ComfyUI：可视化调试和执行视频生成图；以官方 Seedance 2.5 工作流为首个候选。
- Python 媒体服务：封装 FFmpeg/ffprobe、素材归档、时间轴合成、技术质检。对外接受结构化任务，不接受任意 shell 命令。
- PostgreSQL：业务任务、素材索引、远端任务标识、费用、发布状态。业务表与 n8n 内部表隔离。
- 对象存储：生产运行时保存原图、原始片段、音频、字幕、最终成片；本地样片阶段先用任务目录。

先运行单实例 n8n、小并发媒体服务，不因预期规模引入分布式队列和 GPU 集群。ComfyUI 的本地队列和历史不能替代业务任务数据库。

第一版不开发 Vue 控制台。操作入口先使用 n8n、ComfyUI 和简易状态/预览页面；日常操作确实不方便后再增加专用界面。

接入默认先验证 ComfyUI 官方 Partner Nodes，通过 Comfy 账号与积分调用。火山方舟直连属于独立鉴权和计费路径，不能混用密钥。若官方节点在目标账号、地区、自动化环境下不可用或不符合费用要求，再切换经过验证的方舟直连接入；不要同时维护两套完整生产路径。

1. 生产路径只保留一个主力模型加一个草稿模型，避免维护多套完整流程；模型名称在 provider_calls 中作为字段记录，切换不改流程结构。

## 4. 生产工作流

主流程：内容计划 → 选题去重 → 结构化创作方案 → 可选参考图 → 视频生成 → 配音/原生音频 → 时间轴合成 → 质检 → 发布 → 数据回收。

### 4.1 内容计划与创作方案

每个任务绑定内容配置版本：目标受众、选题来源、事实核验要求、画风、声音、时长范围、发布平台、预算。题材后续选择，这里只实现接口和配置结构。

文本模型输出经过程序校验的结构化对象：标题、旁白或对白、镜头目的、画面描述、镜头运动、参考素材、音频模式、预计时长、需要核验的事实及来源。事实性内容缺少可靠来源时不进入自动发布。

统一视觉规范和跨片段参考，减少每个片段独立随机生成造成的风格漂移。不是所有内容都必须先文生图：纯文生视频可以直接调用；只有构图、主体和视觉一致性需要控制时才先生成参考图。

### 4.2 视频生成

先测试官方文本生成视频和参考素材生成视频两种工作流，固定工作流文件、节点版本、模型名称、提示词版本和参数。

第一批验证建议采用 20–40 秒竖屏作品、少量镜头，每个镜头只承担一个明确动作或信息目的。此为工程验证规格，不代表最终题材与账号定位已确定。

多段生成便于局部替换；单次长生成可能减少衔接问题，但返工粒度更大。用同一测试文案比较两者的合格率和实际费用后固定默认模板，不把模型支持的最大时长当作必选时长。

生成流程记录业务任务 ID、Comfy 执行 ID、可获取的供应商任务 ID。供应商标识必须尽可能在等待完成之前持久化；若所选节点不暴露它，则补最小适配层或明确列为接入限制。

生成返回的临时 URL 立即转存。保存来源、校验和、生成参数、工作流版本以及与成片任务的关联。

### 4.3 音频与字幕

两种音频模式明确区分：

- 旁白模式：使用单独 TTS，固定音色、读音词典与语速；以实际音频时长决定时间轴；视频避免生成重复对白。
- 原生对白模式：保留视频模型的声音及对白，验收语义、读音和口型；用转写/对齐生成字幕，不能再覆盖一套不同节奏的旁白。

如果生成音轨无法分离环境声与对白，不假定能无损只删除对白，应改生成设置或重新生成。

字幕优先用可信的 TTS 时间信息或音频对齐结果，不能按文字数量平均分配时间。区分逐句字幕与需要逐词对齐的强调字幕。

### 4.4 合成与封面

FFmpeg 合成服务接收素材 ID 和经过校验的时间轴：顺序、入出点、字幕样式、音量与输出规格。统一帧率、画幅、编码；减少不必要的重复转码。

最终分辨率不等于原始画质，不把低分辨率上采样称为原生高质量。插帧和超分不是默认步骤，仅在样片证明有帮助时启用。

封面优先选用合格的生成帧，标题作为可控文字层叠加。背景音乐来自可使用的素材库，记录来源。所有中间产物可预览、可复用。

### 4.5 质量控制与有限重做

技术检查：可解码、时长正确、分辨率正确、无明显异常黑屏或冻结、无异常静音/削波、字幕在安全区内。黑屏、静止、静音都要结合内容意图判断，不是出现即判失败。

内容检查：结合关键帧、连续片段/视频理解、音频转写检查提示词匹配、明显主体畸变、跨镜头一致性、字幕与语音匹配、信息完整性。只看截图不足以判断动作自然度。

发布前的事实/内容检查与画面质量检查分开记录。模型评分是筛选辅助，不能保证艺术质量或预测高完播率。

初始建议：单镜头最多生成 3 个版本，并同时受单条总预算和每日预算限制。失败原因进入提示词修正，避免无修改地反复抽样。到达上限则暂停该任务，不发布不合格作品。该次数是建议配置，不是已经授权的付费额度。

完成样片人工校准后，正常生产走自动质检、自动发布；只有异常、无法确认或超预算任务需要介入。不会把逐条人工审核作为永久工作流要求。

## 5. 调度与状态

建议拆为 6 个 n8n 子流程：计划与去重、创作方案、素材生成、合成质检、发布、数据回收。不要把所有节点塞进一个难以恢复的大流程。

建议业务状态：queued、planning、generating、rendering、checking、ready、publishing、published、failed、paused、unknown_remote_state。镜头、外部调用、发布尝试分别记录子状态。

关键规则：

1. 业务数据库是任务真相来源，n8n 执行历史用于排查，不承载全部业务状态。
2. 提交付费任务超时不等于提交失败。没有确定结果时标记 unknown_remote_state，按供应商能力对账；不能直接重复提交。
3. Comfy 进程重启后不默认重放整张图；先检查已经转存的产物和远端任务。
4. 状态查询、文件下载与重新生成是不同动作，分别处理重试。
5. 发布同样防重：按账号、内容版本和计划建立唯一发布记录。发布回调不能确认时先查询平台状态。
6. 预算采用“估算预留 + 实际对账”，防止并发任务一起突破上限；收费规则不清楚时不宣称能保证精确硬上限。
7. 实际费用包含被淘汰版本、失败调用中被计费的部分、评估模型及重复下载/存储成本。

建议数据实体：content_jobs、clips、provider_calls、assets、quality_checks、publish_attempts、metrics。每次修改保留内容与工作流版本。

## 6. 发布与复盘

### 6.1 全自动发布执行（必需，技术选型待定）

发布执行是成片通过质检后的最后一个生产步骤，数据回收属于发布后的运营闭环。系统接收成片、封面、各平台文案、内容声明、目标账号和发布时间，自动完成上传、信息填写、提交发布与结果核验；不能仅以生成草稿或上传成功作为完成。

初次账号登录、授权与配置完成后，正常任务不需要逐条人工确认或点击。发布失败应记录原因并按可恢复性处理；结果不明时先核对平台状态，避免重复发布。登录失效等无法自动恢复的异常保留任务状态并提醒处理，不把异常处理设为每条内容的固定人工步骤。

第一阶段只对接一个主平台，后续按需要扩展。官方 API、第三方集成、浏览器自动化或 Skill 均留待发布阶段评估；届时核实平台权限、运行环境、稳定性及结果核验能力。当前不锁定发布技术栈，不安装发布工具。

Video Publisher Skill 已作为候选调研：oil-oil 与 ShenTuZ 两个版本均依赖 Ego Lite，当前存在 Windows 适配限制。因此仅保留参考，不列为实施依赖；不适配 Windows 的候选可直接放弃，后续另选实现。

发布记录标题、封面、素材版本、账号、平台内容 ID（若可获取）、作品链接或其他可核验回执、计划时间、实际时间和结果。区分已提交、审核中、已公开、失败和结果待确认，不把提交成功等同于已公开。

### 6.2 数据回收与复盘

数据采集计划可先设发布后 24 小时、72 小时、7 天，服从接口配额。仅记录实际可读到的播放量、观看时长、完播、分享、收藏、关注转化；拿不到的指标标记缺失，不用播放量推算完播率。

按近似时长、相同平台与内容形式比较。复盘生成下一轮实验建议；只有在预设范围内自动调整一个变量，例如开头结构或镜头密度，避免凭少量数据自动改掉整个账号定位。

## 7. 分阶段实施与验收

### 阶段 A：接入验证和样片标准

交付：官方工作流固定版本、首个 API 成功调用、参考素材规范、音频方案、3–5 条样片及调用记录。

验收：能够得到达到目标视觉质量的成片；所有素材、配置、耗时、尝试次数与可获取费用可追溯；明确最终发布平台和账号权限。

此阶段需要用户的一次性外观/声音偏好校准。模型账户、地区权限、余额和真实单价需要实际核实。

### 阶段 B：单条自动生产闭环

交付：输入内容计划后，自动规划、生成、合成、质检、归档成片；不需要手工搬运素材。

验收：连续运行约 10 个测试任务；完整记录首轮合格率、重做后合格率、有效成片成本、耗时和人工介入次数。样本小，只用于发现流程问题，不作商业效果结论。

必须验证：只替换一个坏镜头；配音修改使依赖时间轴正确更新；下载失败只重下；模型明确拒绝或余额不足能正确终止。

### 阶段 C：可靠性与预算

交付：数据库持久化、恢复流程、防重复提交、限并发、预算预留、日志脱敏、备份。

验收：主动模拟提交超时、返回异常、429、进程重启、磁盘不足和重复触发；确认系统保留已生成结果，不因本地错误无条件重复付费。不能自动恢复的情况进入明确可处理的暂停状态。

### 阶段 D：发布与数据回收

交付：一个主平台的全自动发布执行、状态核验、指标回收、基础复盘。发布工具与技术栈在此阶段确定。

验收：初次账号配置完成后，符合既定规则的成片自动进入发布流程，无需人工搬运、填写或点击最终发布；能核验平台结果并回收其支持的指标；重复执行不重复发布，异常保留明确状态。只停在草稿就绪不算完成发布执行；真实发布能力不能通过假接口验收。

### 阶段 E：持续运行与扩量

交付：定时生产、异常提醒、每日成本与质量统计、每周复盘。

建议试运行 7–14 天，先每日 1–2 条合格成片。依据真实合格率与成本扩量。需要并发扩大时再增加 n8n 队列/Worker，不先上集群。

上述数量、频率、时长均是建议验证参数，实际付费预算尚未设置。

## 8. 部署与维护

本机验证：Windows 运行 ComfyUI；n8n、PostgreSQL、媒体服务可采用容器。仅 API 推理不要求本地高端 GPU，但本地渲染和新增模型节点仍有资源要求。

长期运行：迁移到持续在线的 Linux 主机，定时任务不依赖个人电脑不休眠。初步可按 4 vCPU、8 GB 内存评估单条/低并发，最终按渲染压测调整；这不是已验证的容量承诺。对象存储保存生产素材并制定清理规则。

固定依赖、节点和模型配置，不自动追踪最新版本。升级先回归已保存的样片，再切换生产。

密钥放凭据存储/运行环境，不提交 Git，不放工作流 JSON、不暴露在前端或日志。ComfyUI 和媒体服务仅开放给受控内部网络；n8n 管理入口保护与备份同时配置。

备份包括业务数据库、n8n 数据库及加密密钥、工作流版本、素材索引和关键成片。执行过备份恢复验证后才视为具备恢复能力。

```text
  config\                 非敏感配置、内容模板、输出规格
  prompts\                文案与画面提示词版本
  database\               业务表迁移
  samples\                脱敏的样例输入与验收记录
  tests\                  故障恢复、防重复、合成验证
  deploy\                 容器和部署配置
```

该目录结构为设计，当前只创建了本路线文档。

## 10. 当前尚未决定的输入

首发平台、发布执行技术栈与工具、模型账号与调用权限、单条/每日预算、目标时长、内容定位、音色画风、常驻服务器环境。它们不妨碍架构设计，但影响具体节点参数和发布验收。后续逐项确定，不要求一次回答所有问题。
