# MiniMax H3 本地部署

来源：[魔搭 Comfy-Org/MiniMax-H3](https://modelscope.cn/models/Comfy-Org/MiniMax-H3)。本机使用已有 ComfyUI 0.37.4、Python 3.13 和 PyTorch ROCm 10 环境。

## 选择的模型

主模型采用 `Ref2VA pruned INT8 ConvRot`，适合后续以人物图片、视频或声音作为参考的短剧制作。裁剪去掉可预计算的 AdaLN 大权重，保留原模型的生成主体，并非缩小为另一款小参数模型。INT8 属于 8 位量化。

| 文件 | 保存目录 | 大小（十进制 GB） |
| --- | --- | ---: |
| minimax_h3_ref2va_pruned_int8_convrot.safetensors | ComfyUI/models/diffusion_models/ | 20.97 |
| qwen3vl_32b_minimax_h3_int8_convrot.safetensors | ComfyUI/models/text_encoders/ | 27.14 |
| minimax_h3_video_vae_fp16.safetensors | ComfyUI/models/vae/ | 5.21 |
| minimax_h3_audio_vae_fp32.safetensors | ComfyUI/models/vae/ | 0.61 |

总计约 53.92GB。下载只获取上表文件，不下载整个仓库。每个文件按照魔搭文件清单的 SHA256 校验后才改为最终文件名；下载中的 `.part` 文件不会被 ComfyUI 当成模型加载。

本机 RX 9070 XT 只有 16GB 显存，需内存卸载；并非全模型常驻显存。文本编码器先设置为 CPU，视频采样在 GPU 上执行，视频 VAE 分块解码。小矩阵已验证 ROCm 上的原生 INT8 运算及 ComfyUI INT8 ConvRot 线性层在 CPU/GPU 上均可执行；完整模型是否适用以实际视频验证记录为准。

已完成解码器冒烟验证：64×64、5 帧、24fps 的零潜变量可通过视频/音频 VAE 解码并封装为 MP4，实际解码得到 5 个视频帧及 6400 个音频采样，音轨为 32kHz 双声道。记录为 `.cache/h3-codec-history.json`。这只验证解码与封装兼容性，不代表主模型的画面或对白质量。

完整主模型验证也已通过：四个文件全部校验成功后，原生 ComfyUI 使用本配置生成了橘猫挥手的动画片段。产物为 `runs/20261004_232751_h3_install_check/final/h3_check.mp4`，384×640、124 帧、24fps、5.1667 秒，含 32kHz 双声道音轨。全部视频帧及音频均可解码，音频数值有限且非静音。已检查开头、中间及末尾画面，人物外观保持一致。

这次冷启动任务总耗时 **335.24 秒（约 5 分 35 秒）**，包括模型加载、CPU 文本编码、GPU 采样及音视频解码/封装。采样进度显示 12 步约 54 秒，另有首次模型初始化；不能把采样时间当成整条视频的总耗时。该实测仅对应本页的 384×640、12 步、约 5 秒参数，更大分辨率、参考输入或更长视频需要重新测量。

视频 SHA256：`d355f2cbd42240923d486ee4655b11ef5a3bc82736cfa2c66215a4550a7fc9fc`。任务历史及参数见同批次目录的 `logs/history.json` 和 `config.json`。

## 下载与验证

从项目目录执行，均使用项目内虚拟环境：

```powershell
& ComfyUI/.venv-rocm/Scripts/python.exe services/media/download_h3.py
& ComfyUI/.venv-rocm/Scripts/python.exe services/media/validate_h3.py
```

下载支持断点续传。进度保存在 `.cache/h3-download.json`，后台下载日志为 `.cache/h3-download.log` 和 `.cache/h3-download.stderr.log`。不要同时启动多个下载器。

验证脚本等待本机 GPU 队列空闲，提交 384×640、124 帧、24fps、12 步的中文对白动画测试；时长约 5.17 秒。采样使用 `res_multistep` 和 `simple`，没有安装 CUDA 专用加速节点，也不调用收费接口。它会实际解码输出 MP4，检查尺寸、帧数、帧率及立体声音轨。

结果保存到 `runs/<日期时间>_h3_install_check/`，其中 `prompts/` 保存提示词和工作流，`logs/` 保存 ComfyUI 任务记录，`final/h3_check.mp4` 保存视频。当前验证状态为 `.cache/h3-validation.json`，后台日志为 `.cache/h3-validation.log` 和 `.cache/h3-validation.stderr.log`。

## 修改提示词和参数

提示词为 `prompts/h3_install_check.txt`，参数为 `config/h3_video.json`。每次运行验证脚本会创建新的结果目录。`workflows/h3_int8_validation.json` 可导入本机 [ComfyUI](http://127.0.0.1:8189/) 后编辑；`workflows/h3_int8_validation_api.json` 为 API 格式。

当前工作流使用 Ref2VA 节点但不附参考素材，用于最小文生音视频验证。需要参考图时，可在 ComfyUI 添加 LoadImage 并连接 Ref2VA 的参考图输入。首尾帧 FL2VA 是另外一个权重分支，本次没有下载它。

本次安装不改动 AIMedia 操作台的 Wan 两种生成模式。`config/h3_video.json` 使用独立的验证脚本，不能直接作为现有 `produce_video.py` 的配置；操作台内直接选择 H3 需要后续接入其联合音视频管线。
